GUIA DA SIMULAÇÃO

Entenda o fluxo

Ao criar ou modificar o pedido, SujeitoPedidoLAI chama notificar(). Cada observador inscrito recebe atualizar(), consulta getEstado() e decide se precisa modificar seus resultados.

  1. Registrar pedidoCria o pedido e notifica os observadores inscritos.
  2. Iniciar análiseAltera o estado e provoca novas consultas.
  3. Registrar respostaAdiciona uma resposta e atualiza os indicadores do Painel LAI.
  4. Autorizar publicaçãoMarca o pedido como autorizado, sem publicar os registros ainda.
  5. PublicarBuscaLAI cria seu índice, Dados Abertos exporta metadados e Painel LAI atualiza os contadores.
Ativar e desativar observadores

O botão ATIVO / INATIVO de cada classe controla sua inscrição em Sujeito. Quando está inativa, a classe não recebe atualizar() nas próximas etapas. Ao reativá-la, ela se inscreve novamente e, se houver um pedido, consulta o estado atual imediatamente para se sincronizar. Não são reproduzidas notificações antigas.

Esta tela apresenta as classes Python efetivamente utilizadas pela simulação e os valores atuais dos seus objetos.

  1. Mapa de colaboraçãoMostra as relações entre Sujeito, Observador e suas implementações. Clique em qualquer classe para analisá-la.
  2. Classe analisadaExibe o código-fonte completo da classe selecionada, diretamente do arquivo correspondente. As classes do padrão ficam em codigoFonte/ e a orquestração em simulacao.py.
  3. Auditoria dos objetosMostra os valores atuais das instâncias depois da etapa executada. Classes abstratas não possuem instância própria.
  4. Avançar ou reiniciarExecute a próxima etapa sem sair desta tela. Quando o pedido for publicado, use Reiniciar pedido para começar novamente.
Como interpretar o fluxo

O sujeito notifica os objetos inscritos. Cada observador concreto consulta o pedido e atualiza apenas a informação sob sua responsabilidade. A auditoria mostra o resultado após cada ação.
