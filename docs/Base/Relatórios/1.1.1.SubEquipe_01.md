### GoF Comportamental — Observer

#### Contexto (Problema)

O desenvolvimento considerou um cenário de pedidos de acesso à informação inspirado nas funcionalidades apresentadas pelo Informa.BR. Nesse cenário, diferentes componentes, como um painel de indicadores, a BuscaLAI e a disponibilização de dados abertos, podem precisar reagir a alterações no estado de um pedido.

Sem uma solução de desacoplamento, a classe responsável pelo pedido teria de conhecer diretamente os componentes interessados e acionar a implementação específica de cada um. A inclusão ou remoção de um componente exigiria alterações nessa classe, aumentando a dependência entre as implementações e dificultando a manutenção.

Com base no conteúdo estudado nas aulas da professora, foi interpretado que o **Observer** seria o padrão de projeto mais adequado para aplicar nesse cenário.

Os arquivos de apoio à simulação ficam fora de `codigoFonte/`: [`padrao.py`](https://github.com/UnBArqDsw2026-2-Turma02/2026.2-T02-_G5_ProjetoGovernoEletronico_Entrega_03/blob/main/docs/Base/Relat%C3%B3rios/Artefatos_SubEquipe_01/observer_lai_demo/padrao.py) centraliza as importações; [`simulacao.py`](https://github.com/UnBArqDsw2026-2-Turma02/2026.2-T02-_G5_ProjetoGovernoEletronico_Entrega_03/blob/main/docs/Base/Relat%C3%B3rios/Artefatos_SubEquipe_01/observer_lai_demo/simulacao.py) contém `MotorSimulacao`, que instancia as classes, controla as etapas, gerencia inscrições e registra as chamadas; [`servidor.py`](https://github.com/UnBArqDsw2026-2-Turma02/2026.2-T02-_G5_ProjetoGovernoEletronico_Entrega_03/blob/main/docs/Base/Relat%C3%B3rios/Artefatos_SubEquipe_01/observer_lai_demo/servidor.py) disponibiliza a interface por HTTP; e [`static/`](https://github.com/UnBArqDsw2026-2-Turma02/2026.2-T02-_G5_ProjetoGovernoEletronico_Entrega_03/tree/main/docs/Base/Relat%C3%B3rios/Artefatos_SubEquipe_01/observer_lai_demo/static/) contém HTML, CSS e JavaScript.

O fluxo de execução segue a sequência `SujeitoPedidoLAI.criarPedido()` ou `setEstado()` → `SujeitoPedidoLAI.notificar()` → `ObservadorConcreto.atualizar()` → `SujeitoPedidoLAI.getEstado()` → atualização dos dados internos do observador. O painel permite acompanhar esse fluxo, ativar ou desativar observadores e inspecionar o código e o estado dos objetos após cada etapa. A implementação inclui testes automatizados no diretório [`tests/`](https://github.com/UnBArqDsw2026-2-Turma02/2026.2-T02-_G5_ProjetoGovernoEletronico_Entrega_03/tree/main/docs/Base/Relat%C3%B3rios/Artefatos_SubEquipe_01/observer_lai_demo/tests/), abrangendo o funcionamento e o desacoplamento das classes.
